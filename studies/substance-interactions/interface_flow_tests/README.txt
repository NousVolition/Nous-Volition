WATER INTERFACES AND LARGE-DROP FLOW — COMPLETED COMPUTATIONAL PILOT
Streams and Rocks / NousVolition/Nous-Volition
Date: 17 October 2026

Open report.html for the completed numerical findings and figures.
results.json and the summary CSVs contain the precise saved values.

WHAT WAS RUN
1. Rigid TIP4P/2005 water slabs with two vapor interfaces, on OpenMM's OpenCL
   GPU platform. Three independent primary seeds, each 501 molecules and
   1,000 ps production; 1 fs and 3 nm lateral-size controls, 300 ps each.
   The 700 ps continuations use unchanged physical parameters and count
   with their parent seed. Test-area free energies, planar density profiles
   and fourth-topological-shell classifications are computed from real MD.
2. Fifteen three-dimensional external-flow attempts: two Reynolds numbers,
   grid, domain, lattice speed, shape, seed, closure and low-Re controls,
   plus measured-speed conditions and terminal-force-balance bracketing.
   One no-subgrid-viscosity run failed its numerical guard; it is retained
   and excluded from physical drag comparisons. Check the status column.
3. Short 1/2 fs unthermostatted energy controls, analytical shear-wave
   refinement, uniform-flow and molecular-pair checks, and saved-data audits.

READ THE LIMITS WITH THE RESULTS
Water surface-tension measurements are new to this project but share an
IAPWS absolute calibration. They do not validate the topology populations.
The flow body is fixed and no-slip: no liquid circulation, deformation,
oscillation, particles or capture are simulated. Numerical grid/domain/time
sensitivity remains visible. New falling-drop speeds do not have fully
matched shape and air conditions. These are conditional comparisons, not
validated smoke collection. No physical parameters were fitted to the new
values, but the comparison was not formally blinded. Future changes that
use these results make these measurements development evidence.

REPRODUCE THE SAVED ANALYSIS (CPU)
Use Python 3.12 or later, NumPy, SciPy and Matplotlib. From this folder:
  python analyze.py
  python audit_saved.py
  python make_report.py
All analysis inputs are included: complete sampled energy/force CSVs,
20 ps-spaced molecular analysis frames, and stored flow slices. The source
topology algorithm is bundled unchanged in topology/water_topology.py.
Analysis snapshots include their original indices. The dense 1 ps water
trajectories and final states are retained locally by the original run;
their hashes and sizes are in raw_local_manifest.json, and the dense files
are not required to reproduce the published analysis. Full trajectories
can be regenerated by the simulation scripts; GPU arithmetic and random
integration mean bitwise identity on another device is not promised.

REPEAT THE SIMULATIONS (GPU)
Use a fresh copy of this folder without water/ and flow/ results if you want
to rerun every case. Preserve the published copy as a comparison record.
Install requirements.txt in an isolated Python environment. OpenMM needs
an available OpenCL platform; CuPy needs NVIDIA CUDA 12 and a compatible
driver. The original machine used an RTX 3080, 10 GB. Memory and runtime
requirements rise quickly with finer grids. Then:
  python run_all.py

The driver runs sequentially, skipping completed named folders, then runs
the checks and analysis. The retained Cs=0 failed attempt is expected to
stop early; recording that failure is part of the study. An individual
case can be repeated with a different --name using water_md.py or
flow_lbm.py. extend_water.py continues a saved water final state.
The convenience gpu_environment.py only activates workspace-local NVIDIA
wheels when present on the original Windows host; standard CUDA installs
need no such folder. It does not change machine-wide settings.

NUMERICAL AND SCIENTIFIC RECORDS
- protocol.json: design fixed before numerical runs, with independence limits
- amendments.json: mass-roundoff fix, sampling extension, force-balance grid
- runtime_verification_initial.json: original failed mass check, preserved
- runtime_verification.json: corrected analytical/runtime checks
- nve_check.json and nve_energy.csv: actual energy-control results
- test_analysis.py: independent normalization, geometry and force-balance tests
- saved_data_audit.json: results audit; not an empirical-validation certificate
- measurements.csv and source_audit.json: exact source locations and eligibility
- manifest.json: published file SHA-256 hashes

The initial float-mass error was fixed before the production flow cases.
Main solver source hashes are in every run's metadata. Production water
exchanges energy with a thermostat; production flow has inlet/outlet mass
flux. Closed-system conservation is checked in the appropriate controls.
No gas exposure, new reaction claim or new Navier–Stokes law is involved.
