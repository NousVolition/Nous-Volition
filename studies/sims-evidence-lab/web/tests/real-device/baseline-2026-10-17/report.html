Method and limits

Appium/WebDriver sessions ran on BrowserStack physical iPhone and Android devices. Buttons, sliders, swipes and links used W3C touch pointer actions. Trusted touch events and resulting page state were observed. Select options used WebDriver selection. Seed entry used the iOS native text field and Done button, and Android native key events. JavaScript read page state and positioned elements for interaction; it did not synthesize application input events.

The full control pass covered the four distinct models. The Latest run and Repeated rounds aliases received loading/navigation checks. Rotation was exercised on Network. Representative select values were exercised; every combination, phone model, OS version and network condition was not tested. The runtime error listener was installed after each page loaded, so the separate readiness checks provide the startup evidence.

Changes

No application source changes or new deployment were needed. The test driver was corrected for iPhone screen coordinates, null responses, native keyboard editing, hidden-stage controls and slider thumb targeting. Original failed attempts are preserved below with their passing retests.
